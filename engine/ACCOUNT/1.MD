# ACCOUNT — the real Binance account

Everything here is about the **live** futures account, not the demo one.
Written 2026-11-27.

---

## 1. What exists

```
domain        https://fapi.binance.com      live market + live account
keys          binance/keys/live.json        { "key": ..., "secret": ... }
created       Binance → API Management → System generated → "live"
permissions   Enable Reading, Enable Futures      (withdrawals OFF)
IP lock       196.96.212.249                (the machine's public IP)
server        GET /api/balance              wallet + available, cached 15 s
header        top right of the app shows `available` USDT
```

**Why the IP lock matters:** Binance deletes any key that has trading
permissions and no IP restriction. The red line on the API page says exactly
that. If the ISP changes the IP, the API answers `-2015` and the fix is to add
the new IP to the same key — nothing is lost.

## 2b. The code that owns trading

```
account.py   READ   balance · usdt · account · positions · open_orders ·
                    algo_orders · leverage · set_leverage · margin_type ·
                    income · summary
trade.py     WRITE  limit_entry · market_entry · stop · take_profit ·
                    protect · cancel · cancel_algo · cancel_all ·
                    close_position · open_trade
1.MD         this file
```

**Hard rules already inside `trade.py`:**
```
every entry is a post-only LIMIT (GTX) - rejection beats paying taker fee
every entry is followed by a stop + target; if the stop fails, entry is cancelled
quantity rounded DOWN to step 0.01, price rounded to tick 0.01
MAX_QTY = 0.05 BNB - raise it deliberately, never by accident
conditional orders use /fapi/v1/algoOrder with algoType=CONDITIONAL (-4120 otherwise)
open_trade() is the only function that opens risk
```

**Smoke test (safe, reads only):**
```
cd engine\ACCOUNT
python account.py     prints the live summary
python trade.py       prints tick / step / min qty
```

## 3. How the account is read

**Every route below was called against the live account on 2026-11-27 and
returned data, not an error.** The docs pages are listed next to them.

```
GET  /fapi/v2/balance            OK   list, per-asset wallet + available
GET  /fapi/v2/account            OK   balances, positions, permissions
GET  /fapi/v1/openOrders         OK   list[0]
GET  /fapi/v1/openAlgoOrders     OK   list[0]   conditional orders live here
GET  /fapi/v1/leverageBracket    OK   list[1] symbol + brackets
GET  /fapi/v2/positionRisk       OK   list[*] entry, leverage, marginType
GET  /fapi/v1/income             OK   list
GET  /fapi/v1/multiAssetsMargin  OK   { multiAssetsMargin }
GET  /fapi/v1/positionSide/dual  OK   { dualSidePosition }
GET  /fapi/v1/positionRisk       404  does not exist - use v2 or v3
```

Docs:
- Balance V2 — https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Account-Balance-V2
- Account info — https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Account-Information-V2
- Position information v2 — https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Position-Information-V2
- Leverage bracket — https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Notional-and-Leverage-Brackets
- Income history — https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Get-Income-History
- Open orders — https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Current-All-Open-Orders

**Conditional orders (docs, verified in the old project too):**
- New Algo Order — `POST /fapi/v1/algoOrder`
  https://developers.binance.com/legacy-docs/derivatives/usds-margined-futures/trade/rest-api/New-Algo-Order
  `algoType=CONDITIONAL` supports **STOP_MARKET, TAKE_PROFIT_MARKET, STOP,
  TAKE_PROFIT, TRAILING_STOP_MARKET**. The plain `/fapi/v1/order` route answers
  `-4120 Order type not supported` for these.
- Current All Algo Open Orders — `GET /fapi/v1/openAlgoOrders`
  https://developers.binance.com/legacy-docs/derivatives/usds-margined-futures/trade/rest-api/Current-All-Algo-Open-Orders
- Query Algo Order — `GET /fapi/v1/algoOrder`
- Cancel Algo Order — `DELETE /fapi/v1/algoOrder`

**Flat-account quirk (found by probing, not by reading):** while the wallet is
empty, `positionRisk` returns **no rows at all**, so `leverage()` and
`margin_type()` return `None`. That is Binance, not a bug in `account.py`; both
fill in as soon as a position exists.

The server lives in `engine/footprint/server.py`. It serves the page and the
two JSON routes (`/api/footprint`, `/api/balance`). **It refuses to place orders
on a non-live base unless that base is explicitly configured** — that guard is
deliberate and must be lifted on purpose, never by accident.

## 4. Order rules (written before the first trade)

```
symbol        BNBUSDT perpetual
size          0.01 BNB first      (~$5.5 notional at 555)
risk          stop defines it, never the size
entry         limit at the level — never a market order
stop          stop-limit or stop-market, always attached in the same breath
target        2R, or exit after 3 bars
max positions 1
daily loss cap   $2
```

**Fees, in the only form that matters:**```
taker 0.04% / side → 0.08% round trip
fees as share of risk = 0.08% / stop%
  stop 0.15%  → 53%   unplayable
  stop 0.35%  → 23%   minimum
  stop 0.60%  → 13%   comfortable
```
A setup whose stop is under 0.35% of price is **skipped**, not traded.

## 5. The signal we trade

```
1  OPEN INTEREST   from /futures/data/openInterestHist, 5m rows
                   printed as:  arrived HH:MM:SS   +56 BNB added
2  bars            last four 5m candles + bid x ask grid
3  decision        OI positive → long · OI negative → short
                   stop beyond the signal bar's opposite extreme
```

Rate limit note: the OI row for a 5m window appears **roughly 1–3 minutes
after the window closes**. The `arrived` time is the first moment our server
saw that row and is stored in `engine/footprint/BALLAST/seen.json`.

## 6. Things that must never happen

```
secret pasted into chat, logs, or a commit
withdrawals permission enabled
market orders placed to "get in fast"
size increased after a loss
more than one position open
trading from a machine whose IP is not on the key
```

`binance/keys/` is gitignored. If any key leaks, delete it on Binance first,
then rotate the file. The file has no value without the IP lock — keep it locked.
